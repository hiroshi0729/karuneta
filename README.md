# カルネタ

## 1. サービス概要

- 思いついた投稿ネタを、投稿できる構成まで育てる。Instagramカルーセル投稿の企画・構成管理アプリです。
- カルーセルで集客している個人事業主が、思いついたネタをスマホで1行メモし、構成テンプレートを使ってスキマ時間に1枚ずつの文章まで仕上げておくことで、投稿日に「何を出そう」と手が止まらない状態をつくります。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

- いつ：2026年秋ごろ、自分の事業（Web制作・集客支援）のInstagram運用で、カルーセル投稿を続けようとしていたとき。
- どんな状況で：ネタはスマホのメモアプリ、スプレッドシート、Figmaにバラバラに置いていました。投稿日が来てから「今日は何を出そう」と探し始め、ネタが決まっても、表紙からまとめまでの1枚ずつの見出しと本文を考えるのに時間がかかりました。あとで見返すと、同じカテゴリの投稿ばかりが続いていたこともありました。
- どんな気持ちになったか：お客さんには「発信は続けることが大事」と伝えている立場なのに、自分の発信は準備が追いつかずに止まりかける。そのことに焦りと、少しの気まずさを感じました。

具体的には、Instagram集客を本格的に始めるにあたり、投稿の柱として「Web集客」「Web改善事例」「便利ツール」の3つのカテゴリを決め、カルーセル形式で発信していくことにしました。

ところが投稿予定日の当日になってから、メモアプリとスプレッドシートを行き来してネタを探し始めることがよくありました。ようやくネタを決めても、表紙の一言から最後の「保存してね」までの構成を考えているうちに時間が過ぎ、その日の投稿を見送ったこともあります。

そんな週が続いたあとに投稿を見返すと、手を付けやすい「Web集客」の投稿ばかりで、「改善事例」や「便利ツール」はほとんど出せていませんでした。カテゴリまで決めて準備したつもりだったのに、その通りに続けられていないことにショックを受けました。

---

### 2-2. なぜそれが「気になった」のか

- 仕事柄：Web集客の支援をしていて、お客さんに「発信を続けることが成果につながる」と伝える側にいます。自分ができていないことは、人にもすすめにくいと感じました。
- 性格：段取りや仕組みで、ムダな作業を減らすのが好きです。毎回ゼロから構成を考えている状態は「仕組みがあれば減らせるムダ」に見えました。
- 過去の経験：以前にもSNSでの発信を始めたことがありましたが、ネタ探しと構成づくりの負担が積み重なり、更新が止まってしまいました。続かなかったのは気持ちの問題ではなく、「準備の仕組みがなかったから」だと考えています。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

投稿日になっても、何を投稿するか決まらず手が止まってしまう。

---

### 3-2. 本当に解決したい課題は何か

- なぜ？ → 投稿できる状態のネタが一目で分からないから。ネタがメモアプリ・スプレッドシート・Figmaに散らばっている。
- なぜ？ → 思いついたネタが「1行メモ」のまま放置され、カルーセルの構成まで育てる場所とタイミングがないから。
- なぜ？ → 構成を考える作業がFigmaでのデザイン作業と一体になっていて、「時間があるときにまとめてやる」ものになり、気軽に手を付けられないから。

→ 本当に解決したい課題：思いついたネタを、投稿できる形（1枚ずつの構成）に少しずつ育てる行動が習慣になっておらず、投稿日に焦って発信が途切れてしまうこと

---

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

Instagramのカルーセル投稿で集客している、ひとりで事業をしている個人事業主（Web制作・コンサル業など）

年齢設定：
- 年齢：30代
- 理由：事業を始めて集客の手段としてInstagramを使い始めたものの、本業が忙しく発信の時間をまとめて取れない世代だから。

生活・状況設定：
- 生活・状況：日中は本業（制作・打ち合わせ）。発信のネタは移動中や作業の合間にふと思いつくが、その場では構成まで考える時間がない。
- 理由：思いついた瞬間に1行で残し、あとのスキマ時間に1枚ずつ構成を足していけるので、「まとまった時間がないと進まない」状態を解消できる。

環境設定：
- 環境：ネタを思いつくのはスマホ、デザイン（Figma等）を作るのはPC。
- 理由：スマホでも入力しやすい画面にし、PCでデザインを作るときには構成がそのまま見られるようにすることで、「スマホのメモをPCに移す」手間をなくす。

---

### 4-2. 自分とユーザーの距離

- 自分自身

→ 自分が今まさにカルーセル投稿の準備で困っている当事者だからです。どこで手が止まるか、どんな画面なら続けられるかを、自分で使いながら確かめられます。

---

### 4-3. 実際に使われる可能性について（需要・存在確認）

- まず最初に使ってくれそうな人：自分自身。次に、同じようにInstagramで集客しているフリーランスや小さなお店のオーナー。
- どんな場面で思い出すか：ネタを思いついた瞬間と、「そろそろ次の投稿を準備しなきゃ」と思ったとき。
- 今代わりに使っているもの：スマホのメモアプリ、スプレッドシート、Figma。
- 置き換えてまで使う理由：今のツールは「ネタを置く場所」「構成を考える場所」「投稿日を決める場所」がバラバラです。このアプリでは1つのネタがそのまま構成になり、投稿予定日とともにホーム画面に並ぶので、移し替えの手間と「どこに書いたっけ」がなくなります。

---

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ（導入・継続の流れ）

- 知る・思い出すきっかけ：投稿日に「何を出そう」と手が止まったとき。
- 最初の一歩：ユーザー登録 → 投稿カテゴリ（例：Web集客／改善事例／便利ツール）を作る → 思いついているネタを1行ずつ登録する。
- 使い続ける理由：
  - ネタのストックが増えるほど「次に出せるものがある」という安心感がある
  - アプリを開くと「投稿予定が近いネタ」「構成中のネタ」が並び、次に何をすればいいかがすぐ分かる
  - カテゴリごとの投稿件数が表示され、投稿内容の偏りにすぐ気づける

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

- サービス名：Meta Business Suite（Meta公式）
- URL：https://business.facebook.com/
- どんなことができるか：Instagram・Facebookの投稿作成、予約投稿、カレンダーでの投稿管理、分析。

- サービス名：Later
- URL：https://later.com/
- どんなことができるか：Instagramなどの予約投稿、カレンダーでのコンテンツ管理。

- サービス名：Notion／スマホのメモアプリ
- URL：https://www.notion.so/
- どんなことができるか：自由にメモやデータベースを作り、ネタを管理できる。

---

### 5-2. それでも自分が作りたい理由

- 予約投稿ツールは、画像とキャプションが完成してから使うものだと感じました。自分が手を止めているのはその手前の「ネタを構成に落とし込む」段階で、そこを助けてくれる場所がありませんでした。
- メモアプリは書きっぱなしになり、あとから探せません。スプレッドシートはスマホで入力しづらく、思いついた瞬間に書けません。
- Figmaに直接書くと、構成を練る前にデザインの作り込みに入ってしまい、中身を考える時間が減ってしまいます。
- Notionなら作り込めば近いことはできますが、自分で仕組みを作り、維持する手間がかかります。

---

### 5-3. 差別化を「体験価値」で表現する

このアプリは、【カルーセル投稿で集客している個人事業主】の【思いついたネタを、投稿できる形まで育てる瞬間】を一番助けるアプリです。

- 私のアプリの差別化ポイント：移動中にスマホで1行メモしたネタを、構成テンプレートを選ぶだけで骨組みにし、スキマ時間に1枚ずつの文章まで育てておけるので、投稿日には「出せるもの」がすでに揃っている

Meta Business Suiteなどの投稿管理・公開機能そのものではなく、その手前の「企画・構成づくり」に特化します。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- 行動の変化：投稿日の当日に考え始めるのではなく、事前に構成まで仕上がったネタから選んで投稿するようになる。
- 気持ちの変化：「今日何を出そう」という焦りが、「ストックがあるから大丈夫」という安心に変わる。
- 考え方の変化：投稿を「その日にこなす作業」ではなく、「少しずつ育てるもの」と捉えるようになる。

### 6-2. 価値を一文で表す

「このサービスは、カルーセル投稿で集客している個人事業主が、投稿日に手を止めずに発信を続けられるようになるサービス」

## 7. このアプリで実現すること

### MVPで作る機能

- ユーザー登録・ログイン・ログアウト
- ネタの登録（タイトル1行だけでも登録できる）・一覧・編集・削除
- ステータス管理（ネタ／構成中／投稿準備完了／投稿済み）と、ステータス別の絞り込み
- カルーセル構成テンプレート（「ノウハウ紹介型」「チェックリスト型」の2種類から選ぶと、各スライドの見出しのひな形が入る）
- カルーセル構成エディタ（各スライドの見出し・本文を編集し、スライドを追加・削除できる。最大10枚）
- カテゴリ管理（カテゴリ名と色を設定し、ネタ一覧で色分け表示）
- 投稿予定日の設定
- ホーム画面（次にやることが分かるダッシュボード）
  - 投稿予定が近いネタ
  - 構成を作成中のネタ
  - まだ着手していないネタの件数／投稿済みの件数
  - カテゴリ別の投稿件数（直近10件）
- スマホ表示への対応

### 本リリースで作る機能

- 投稿予定の月カレンダー表示
- スライドのドラッグ＆ドロップでの並び替え
- 各スライドのテキストをワンクリックでコピー（デザイン作業へ貼り付けやすくする）
- キャプションの入力と文字数カウント
- ハッシュタグセットの保存と呼び出し
- カテゴリ別の投稿割合のグラフ表示（MVPでは件数表示）
- 自分で構成テンプレートを作成・保存する機能（過去の投稿を複製してテンプレート化）
- 投稿予定日のリマインド通知（メール）
- ネタのキーワード検索

### 対象外にする機能（将来の拡張として検討）

- AIによる投稿文章の自動生成
- InstagramとのAPI連携・予約投稿
- Canva・Figmaとの連携、画像やカルーセルデザインの自動生成
- Instagramのインサイト分析
- 複数ユーザーでの共同編集

## 8. このアプリの懸念点とその対策

### 懸念点①

- 何が問題になりそうか：ネタを登録するのが面倒になり、結局メモアプリに戻ってしまう。
- なぜそう思うか：自分自身、思いついた瞬間に手間がかかる方法は続かなかったから。
- そのために考えている対策：ネタはタイトル1行だけで登録できるようにし、スマホで開いてすぐ入力できる画面にする。構成やカテゴリはあとから足せばよい設計にする。

### 懸念点②

- 何が問題になりそうか：「メモアプリやNotionで十分」と思われ、使い始めてもらえない。
- なぜそう思うか：ネタを書くだけなら、既存のツールでもできてしまうから。
- そのために考えている対策：機能を広げすぎず、「カルーセルの1枚ずつの構成を考える」体験に絞り込む。構成テンプレートを選ぶだけで骨組みができるようにし、白紙から考える負担を既存ツールより軽くすることに集中する。

## 9. 今後の展開・発展の方向性

### 観点

- ユーザーはなぜ使い続ける？：ストックがあることが安心につながり、使うほど投稿の準備が楽になるから。
- 続けることで何が変わる？：発信が途切れにくくなり、投稿の量と質が安定する。
- データが溜まると何ができる？：過去の構成をテンプレートとして再利用できる。カテゴリ別の投稿数から、発信の偏りや得意なテーマが見えてくる。
- 他の人と関わる余地はある？：将来的に、デザイン制作を任せる相手へ構成を共有できるようにする。

### 今考えている発展案

- 機能追加の方向性：投稿後の反応（保存数・いいね数）を手入力で記録し、反応が良かったカテゴリや構成を振り返れるようにする。
- UI・体験の改善：スマホでの構成入力をさらに楽にする（1枚ずつスワイプで編集する画面など）。
- 機能以外の工夫：自分の投稿で使いながら改善し、同じ悩みを持つ個人事業主に使ってもらってフィードバックを集める。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 8系
- DB：PostgreSQL
- デプロイ先：Render（無料プラン）
- 使用予定ライブラリ：
  - 認証：sorcery（パスワードのハッシュ化に bcrypt）
  - CSS：Tailwind CSS
  - フロント：Hotwire（Turbo／Stimulus）
  - テスト：rspec-rails、factory_bot_rails
  - コード品質：rubocop、rails_best_practices
  - デバッグ：pry-rails、pry-byebug、better_errors

---

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | カリキュラムで学んだ技術で、CRUDと認証を確実に作れるため |
| Next.js（React） | 不採用 | 学習コストが高く、MVPリリースまでに完成させるのが難しいため。本リリース後の検討とする |
| sorcery | 採用 | カリキュラムで学んだ認証Gemで、ログイン・ログアウトに必要な機能だけを最小限の設定で実装できるため |
| Rails 8標準の認証ジェネレーター | 不採用 | ログイン機能は生成されるが、ユーザー登録機能は自分で作る必要があるため。学習済みのsorceryの方が確実に実装できる |
| Devise | 不採用 | 多機能だが設定やカスタマイズの把握に時間がかかり、MVPに必要なのはシンプルなログイン機能だけなため |
| Hotwire（Turbo／Stimulus） | 採用 | Rails標準で、スライドの追加・削除をページ遷移なしで行えるため |
| 構成テンプレートをコード内の定数で持つ | 採用 | MVPのテンプレートは2種類で固定のため、テーブルを作らずシンプルに実装できる |
| 構成テンプレートをDBのテーブルで持つ | 不採用（本リリースで検討） | ユーザーが自作テンプレートを保存する本リリースの機能で必要になるため、そのタイミングで移行する |
| simple_calendar | 不採用（本リリースで検討） | MVPでは、ホーム画面の「投稿予定が近いネタ」一覧で投稿日を確認できれば十分なため |
| FullCalendar（JS） | 不採用 | ドラッグ操作など高機能だが、JSの設定コストが大きく、MVPには不要なため |
| Render（無料プラン） | 採用 | 無料でRailsアプリとPostgreSQLを公開でき、Railsのデプロイ手順もシンプルなため。無料のDBは作成から30日で期限切れになるため、卒業後も公開を続ける場合は有料プランへの移行を検討する |
| Tailwind CSS | 採用 | スマホ対応のレイアウトをクラスで素早く組めるため |

- 今回チャレンジしたい点：1つの投稿に複数のスライドがぶら下がる構造を、Turboを使ってページ遷移なしで追加・編集できるようにすること。テンプレートを選んだときに、スライドをまとめて作成すること。
- 不安な点：構成エディタ（複数スライドの同時編集）の実装にかかる時間の見積もり。

---

### 10-3. キャッチアップ不足の懸念

- MVPでは、カリキュラムで学んだRailsの範囲で作れる機能に絞ります。
- スライドのドラッグ並び替え（JSライブラリが必要）や通知機能は本リリースに回し、MVP完成後にキャッチアップしてから組み込みます。
